# fairytale-docs-bot

Telegram-бот "Довідник лісу", який відповідає на питання звірів на основі документів із порадами. Він знає стандартні документи з "Лісового архіву" на Google Диску, приймає нові документи від звірів (PDF, Word, TXT) і в кожній відповіді вказує джерело: назву документа й місце, для якого він написаний, а для документа від звіра ще й автора та час надсилання. Бот лише для своїх: увійти можна за запрошенням від сусіда.

Вимоги та рішення, погоджені із замовницею: [REQUIREMENTS.md](REQUIREMENTS.md). Розмова із замовницею: [docs/dialog.md](docs/dialog.md).

## Запуск

Потрібен Docker з Docker Compose.

1. Створіть бота в [@BotFather](https://t.me/BotFather) і скопіюйте токен.
2. Отримайте безкоштовний API-ключ на [console.groq.com](https://console.groq.com/keys).
3. Скопіюйте приклад налаштувань і впишіть токен та ключ:

   ```bash
   cp .env.example .env
   ```

   Файл `.env` не обов'язковий: ті самі змінні можна задати в оточенні, наприклад `export TELEGRAM_BOT_TOKEN=... GROQ_API_KEY=...`.

4. Запустіть:

   ```bash
   docker compose up --build
   ```

Бот одразу починає приймати повідомлення. Під час першого запуску він завантажує "Лісовий архів" і розпізнає скановані PDF, це займає близько двох хвилин; питання, що прийшли раніше, чекають, і бот попереджає про це звіра. Дані (документи, імена звірів) зберігаються в `./data/bot.db` і переживають перезапуск, тож далі архів уже під рукою з першої секунди.

5. Бот лише для своїх, тож у журналі запуску з'явиться запрошення для першого звіра:

   ```
   The bot is open only by invitation. Invite for the first animal: https://t.me/<бот>?start=inv_...
   ```

   Знайти його можна командою `docker compose logs bot | grep inv_`; якщо написати боту без запрошення, поки в ньому ще нікого немає, він сам підкаже, де шукати. Відкрийте це посилання в Telegram, і далі запрошуйте інших командою `/invite`. Нове посилання для ще одного звіра дає команда `docker compose run --rm bot python -m bot.invite`. Щоб бот відповідав усім, задайте `INVITES_ONLY=false`.

Перевірити відповіді без Telegram:

```bash
docker compose run --rm bot python -m bot.ask "скільки внесок під дубом?"
```

Прогнати еталонні питання на живій моделі (серед них контрольне питання замовниці; кожна відповідь має містити очікувані факти й джерело):

```bash
docker compose run --rm bot python -m bot.check
```

## Як користуватися

- Питання пишіть звичайним текстом і називайте місце: "скільки внесок під дубом?", "які гриби біля сосон?", "що робити при пожежі?". Якщо відповідь залежить від рукавички, а місце не назване, бот перепитає й запропонує обрати рукавичку кнопкою. Після відповіді можна коротко уточнити інше місце ("а у соснах?"), і бот відповість на те саме питання для нього. На "привіт" чи "дякую" бот відповідає сам, не шукаючи поради.
- Пораду надсилайте файлом PDF, Word (.docx або старий .doc) чи TXT; інші текстові файли (наприклад, .md) теж підходять. Під час першого документа бот попросить назватися (підтвердити ім'я можна кнопкою або словом "так"). Місце можна вказати в підписі до файлу ("для Під вербою", "для хвойного лісу"); якщо підпису немає і з документа незрозуміло, для якого він місця, бот запитає: місце можна обрати кнопкою або написати ("під дубом", "увесь ліс"). Кожен документ стосується одного місця: рукавички, частини лісу або всього лісу. Путівник із порадами для кількох рукавичок зберігають для частини лісу, до якої вони належать, або для всього лісу. Для кожного питання модель бере з нього розділ про потрібне місце, але такий розділ важить як увесь документ, тож порада для самої рукавички важливіша (так вирішила замовниця). Місце можна змінити кнопкою "Змінити місце".
- Щоб замінити свій документ, надішліть новий файл із тією самою назвою. `/my` показує ваші документи й дає їх видалити.
- `/help` пояснює правила, `/cancel` скасовує поточну дію (і каже, які документи через це не збережено), `/invite` дає запрошення для сусіда, `/invited` показує запрошених, `/name` змінює ім'я, яким бот підписує документи звіра, зокрема вже надіслані.
- Якщо, поки документ чекає на ім'я чи місце, звір замість відповіді ставить питання ("скільки внесок під дубом"), бот відповідає на нього і знову просить ім'я чи місце, а документ не зберігає навмання.
- Аватарку (дубовий лист і сторінка на бересті, `bot/assets/avatar.jpg`) бот ставить собі сам під час першого запуску, якщо не задано `SET_BOT_PROFILE=false`.

### Доступ лише для своїх

Бот відповідає лише звірам наших рукавичок: тим, хто прийшов за запрошенням. Адмінів немає: будь-який звір, який уже в боті, робить запрошення командою `/invite` і пересилає сусідові. Запрошення одноразове й діє 7 днів, а бот запам'ятовує, хто кого запросив. У списку `/invited` звір, який ще не назвався боту, показаний іменем із Telegram, щоб його можна було впізнати. Якщо запрошений виявився чужим, той, хто його запросив, або будь-хто вище в ланцюжку запрошень закриває йому доступ командою `/invited`: доступ втрачають і всі, кого запросив чужий, їхні документи бот більше не використовує, а їхні невикористані запрошення гаснуть. Якщо доступ закрито помилково, сусід запрошує звіра знову, і його документи повертаються. Чужому без запрошення бот пояснює, що треба попросити запрошення в сусіда. Перше запрошення бот пише в журнал під час запуску, або його можна отримати так:

```bash
docker compose run --rm bot python -m bot.invite
```

## Як це працює

```
Telegram ──> handlers ──> файл:  extract (PDF/DOCX/TXT, OCR сканів) ──> classify (місце) ──> storage
                     └──> текст: answering ──> places (місце з питання, карта лісу, мешканці зі статутів)
                                          ──> search (BM25 серед порад для цього місця, окремо на кожному рівні)
                                            + легка модель Groq обирає документи за назвами
                                          ──> Groq (відповідь лише з наданих документів) ──> джерела
Google Диск ──> archive (кожні 10 хв) ──> storage (версії, чинна лише одна)
```

- **Місця.** `bot/places.py` знає вісім рукавичок і три частини лісу. Карта (яка рукавичка в якій частині) перечитується з документа "Карта лісу", тож її зміна в архіві змінює й правила. Порада для рукавички застосовується лише до неї, порада для частини лісу до рукавичок цієї частини ("Під вербою" належить до двох, "На узліссі" до жодної), порада для всього лісу до всіх.
- **Пошук.** Бот спершу визначає місце з питання, потім залишає лише поради, що до нього стосуються, і шукає серед них двома способами. BM25 з урахуванням українських закінчень і кількох синонімів ("що їсти" й "чим поживитись", "хто живе" й "живуть") бере найкращі документи окремо для рукавички, кожної її частини лісу й усього лісу, тож сильний збіг у загальній пораді не витісняє пораду самої рукавички. Крім того, найлегша модель зі списку (за замовчуванням `openai/gpt-oss-20b`) обирає документи за назвами: так знаходяться поради, які не мають спільних слів із питанням. Документи рукавички йдуть першими.
- **Місце не назване.** Якщо в питанні немає місця, модель бачить і загальні поради, і поради для окремих місць. Якщо відповідь для різних рукавичок різна ("коли утеплювати рукавичку?"), бот перепитує рукавичку кнопками; якщо однакова для всього лісу або питання саме називає, про кого йдеться, відповідає одразу. Хто де живе, бот знає зі статутів рукавичок і визначає це ще до пошуку, тож "коли Ведмідь лягає спати?" він відповідає за правилами рукавички "У ліщині", а "що робить Сова вночі?" за документами "Під дубом".
- **Названа лише частина лісу.** Питання "у хвойному лісі" чи "біля річки" бачить спершу поради цієї частини лісу й усього лісу, а потім поради її рукавичок як винятки: модель відповідає за порадою частини лісу й коротко згадує рукавички, де інакше, а якщо першою ставить пораду однієї рукавички, бот один раз перепитує її. Якщо відповідь є лише в порадах окремих рукавичок і вони різні ("скільки внесок біля річки?"), бот пропонує обрати рукавичку цієї частини лісу, а не каже, що поради немає.
- **Відповідь.** Groq отримує не більше семи документів (коли місце не назване, восьми), відсортованих від конкретніших до загальніших, з позначками рівня, джерела й дати, а також сьогоднішню дату з днем тижня. З довгого документа модель отримує уривок: текст ділиться на шматки за абзацами, рядками й реченнями (у Word і PDF між абзацами часто немає порожнього рядка), заголовок розділу лишається з його текстом, і першими йдуть розділи про місце з питання, знайдені за картою лісу ("біля сосон" знаходить розділ "У соснах"), а потім найближчі за словами. Усі документи разом займають до 12 тис. символів, щоб промпт умістився в хвилинний ліміт Groq: коротші йдуть цілими, довші ріжуться до однакової частки (не менше 1500 символів, тож документи архіву не ріжуться ніколи). Для питань про дати й час додається календар поточного та наступного місяця, щоб "перша субота жовтня" чи "по середах" не рахувалися навмання, і модель думає довше. Модель повертає JSON з відповіддю і номерами документів. Назви джерел, місце, автора й час бот підставляє сам із бази, тому джерело не може загубитися чи бути вигаданим. Відповідь без джерела не показується, замість неї бот чесно каже, що не знайшов поради. Якщо модель першим джерелом ставить загальніший документ, ніж інший процитований (наприклад, розділ "Під дубом" путівника для всього лісу попереду поради для листяного лісу), бот один раз перепитує її, нагадавши рівні документів.
- **Архів.** Синхронізація при запуску й кожні 10 хвилин. Якщо Диск поверне порожній список (змінилася сторінка, збій), бот залишає архів як був, а не стирає його. Змінений файл стає новою версією; файл із такою самою назвою для того самого місця замінює старіший; перейменований файл отримує нову назву, зберігаючи дату поради; видалений з Диска файл перестає використовуватися. Документи Google Docs у теці бот експортує як текст. Усі версії зберігаються в базі, у відповідях бере участь лише чинна.
- **Скановані PDF.** 19 документів архіву є сканами без текстового шару. Сторінки без тексту рендеряться і розпізнаються Tesseract (українська мова). Скан, у якому таких сторінок понад 30, бот просить розділити, а не обрізає мовчки.
- **Стан діалогів** (документ, що чекає на ім'я чи місце, питання, що чекає на рукавичку) зберігається в SQLite і переживає перезапуск. Ім'я ("Мене звати Білочка" стає "Білочка") і видалення документа бот підтверджує кнопками. Якщо на "Про яку рукавичку?" звір відповідає частиною лісу ("у хвойному лісі"), бот пропонує рукавички цієї частини. Питання, що чекає на рукавичку, і документ, що чекає на ім'я чи місце, не витісняють одне одного: кнопки рукавичок діють за будь-якого стану, а останнє повідомлення бота завжди про те, що чекає на відповідь текстом. Кнопки прив'язані до свого питання чи документа, тож стара клавіатура не відповість на інше питання і не збереже наступний документ не туди, а кнопка вже збереженого документа так і каже. Якщо на питання, що чекає на рукавичку, звір відповідає місцем після документа ("у соснах"), бот відповідає саме на нього. /cancel і /start кажуть, які документи не збережено, і зупиняють документ, який бот саме читає чи для якого модель визначає місце. Будь-яка непередбачена помилка не лишає звіра без відповіді: бот перепрошує і просить спробувати ще раз, а подробиці пише в журнал.
- **Документи від звірів.** Кожен документ стосується одного місця. Його визначає адресат на початку тексту: місце одразу після "для" чи "мешканцям" ("Порада для листяного лісу: білі гриби шукайте під дубом" стосується листяного лісу, а не рукавички "Під дубом"; "Порада для всіх:", "Нагадування для всього лісу" — весь ліс) або звертання, що закінчується місцем ("Шановні мешканці лісу!", "Мешканці лісу під ялинами!"). Речення на кшталт "Звірі під ялиною ховаються від дощу" адресатом не є. Якщо адресатів кілька ("для хвойного та листяного лісу"), бот питає. Інакше вирішує назва файлу з одним місцем ("Внески Під дубом", "ВНЕСКИ ПІД ДУБОМ"; "Білі гриби під дубом" з малої літери може бути про будь-який дуб, а "Як дійти до Під дубом" — про дорогу туди), а якщо назва й текст називають різні місця, бот питає. Далі текст: рукавичка, названа саме як своя рукавичка ("у рукавичці Під дубом", "«Під дубом»", але не "до старої рукавички Під дубом"), назва частини лісу ("у хвойному лісі", "під ялинами"; річка — лише коли нею починається рядок: "біля води" посеред поради не каже, для кого вона) або "для всього лісу". Так вирішується без моделі, лише коли ці слова є на перших сторінках; місця на решті сторінок можуть тільки скасувати рішення. Слова-речі ("порічки", "хвойні гілки", "листяна підстилка") місцем не вважаються. Назва дерева в пораді ("рижики ростуть під ялиною") сама не робить пораду рукавичною: тоді модель обирає з місць, що охоплюють увесь документ, а рукавичку бот приймає, лише якщо текст називає її своєю рукавичкою або нею починається ("Під дубом при пожежі збираємося під дубом"). Порада для кількох рукавичок зберігається хіба що для їхньої спільної частини лісу, а порада з розділами для різних частин лісу — лише після питання відправнику. Якщо місце незрозуміле, бот питає відправника кнопками і не вгадує. Той самий звір із тією самою назвою документа для того самого місця замінює свою попередню версію.

Тести покривають розпізнавання місць і правила карти, версії документів, синхронізацію архіву, вибір документів для відповіді, формат джерел і повні діалоги в Telegram (через підставний сервер Telegram і модель). Тест старого Word (.doc) потребує antiword, тож поза Docker він пропускається. Відповіді живої моделі перевіряє `python -m bot.check`.

## Обмеження

- Без `GOOGLE_API_KEY` публічна сторінка теки показує лише дату зміни без часу. Зміну вмісту файлу бот усе одно помічає за хешем і датує моментом, коли її побачив. Якщо ж в архів додати новий файл із такою самою назвою того самого дня, точний порядок версій дасть лише ключ API.
- Безкоштовний рівень Groq дає кожній моделі 8000 токенів на хвилину, 200 тис. токенів і 1000 запитів на день, причому до хвилинного ліміту Groq зараховує і промпт, і максимальну довжину відповіді. Тому питання коштує два запити до різних моделей: вибір документів за назвами на легкій `gpt-oss-20b` (близько 1-2 тис. токенів) і відповідь на `gpt-oss-120b` (3-6 тис.); календар і довше міркування бот додає лише питанням про дати. Запити до однієї моделі йдуть по черзі; коли хвилинний ліміт вичерпано, бот чекає до 25 секунд, а якщо треба довше, бере наступну модель зі списку `GROQ_MODELS`. Коли еталонні питання (`bot.check`) проганялися двічі поспіль, друга половина пішла на запасну модель, і всі відповіді були правильні.
- Добового ліміту `gpt-oss-120b` вистачає приблизно на 35-60 відповідей. Далі відповідає `qwen3.8-27b`, потім `gpt-oss-20b`, тож разом це понад сотню питань на день. Модель, яка вичерпала добовий ліміт, бот не смикає, доки Groq не дозволить знову. Для більшого лісу потрібен платний рівень Groq.
- Без `GOOGLE_API_KEY` бот читає публічну сторінку теки на Google Диску. Якщо Google змінить її розмітку, уже завантажений архів залишиться в базі, але новий екземпляр бота без ключа архіву не отримає; з ключем бот користується офіційним Drive API.
