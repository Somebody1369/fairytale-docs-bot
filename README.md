# fairytale-docs-bot

Telegram-бот "Довідник лісу" відповідає на питання звірів за документами з порадами й під кожною відповіддю називає джерело: документ, його місце, а для документа від звіра ще й автора та час надсилання. Стандартні документи бот бере з "Лісового архіву" на Google Диску, нові приймає від звірів файлами PDF, Word чи TXT.

Вимоги й рішення: [REQUIREMENTS.md](REQUIREMENTS.md). Розмова із замовницею: [docs/dialog.md](docs/dialog.md). Як усе влаштовано: [docs/how-it-works.md](docs/how-it-works.md).

> **Тим, хто перевіряє.** За замовчуванням бот закритий для чужих (`INVITES_ONLY=true`).
>
> - Посилання для першого звіра бот пише в журнал запуску, поки в ньому нікого немає: `docker compose logs bot | grep inv_`. Нове дає `docker compose run --rm bot python -m bot.invite`. Ці посилання одноразові й не мають терміну дії.
> - Посилання з команди `/invite` у боті одноразові й діють 7 днів.
> - Щоб перевіряти з багатьох акаунтів, задайте `INVITES_ONLY=false`: бот відповідатиме всім.

## Запуск

Потрібен Docker з Docker Compose. Токен бота дає [@BotFather](https://t.me/BotFather), безкоштовний ключ Groq — [console.groq.com](https://console.groq.com/keys). Впишіть їх у `.env` (`cp .env.example .env`) або задайте в оточенні, і запустіть:

```bash
docker compose up --build
```

Перший запуск завантажує архів і розпізнає скановані PDF, це близько двох хвилин; питання, що прийшли раніше, чекають. Дані лежать у `./data/bot.db` і переживають перезапуск.

| Змінна | Обов'язкова | Значення |
| --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | так | токен від @BotFather |
| `GROQ_API_KEY` | так | ключ Groq |
| `GROQ_MODELS` | ні | моделі в порядку пріоритету, зайняту бот пропускає; документи за назвами обирає найменша. За замовчуванням `openai/gpt-oss-120b,openai/gpt-oss-20b,qwen/qwen3.8-27b` |
| `DRIVE_FOLDER_ID` | ні | тека "Лісовий архів" |
| `GOOGLE_API_KEY` | ні | ключ Drive API для точного часу зміни файлів; без нього бот читає публічну сторінку теки |
| `ARCHIVE_SYNC_MINUTES` | ні | як часто перевіряти архів, за замовчуванням 10 |
| `TZ_NAME` | ні | часовий пояс, за замовчуванням `Europe/Kyiv` |
| `INVITES_ONLY` | ні | `true` (за замовчуванням): лише запрошені; `false`: усі |
| `SET_BOT_PROFILE` | ні | `true` (за замовчуванням): бот ставить собі назву, опис і аватарку; `false`: лишає задане в @BotFather |

## Як перевірити

1. Дочекайтеся в журналі `Archive loaded` і відкрийте посилання для першого звіра.
2. Поставте питання. Перші п'ять із відповідями дала замовниця.

| Питання | Що має бути у відповіді |
| --- | --- |
| Скільки внесок під дубом і до якого числа? | 4 жолуді з дорослого звіра на місяць, до 10 числа, Кабанові в кошик біля входу, замість жолудів 2 лісові горіхи; "Членські внески рукавички Під дубом" |
| Біля греблі мисливці! Як кричати? | тричі коротко, як Сорока; почув постріл — у гущавину; "Як кричати, коли бачиш мисливців" |
| Через скільки днів після дощу йти по гриби в соснах? | у хвойному лісі на 2-3 день; загальна порада для всього лісу — коли земля волога, але не хлюпає; "Грибний путівник хвойного лісу", "Їстівне й отруйне" |
| Де шукати гриби біля верби? | листяний ліс: білі під дубами, підберезники біля беріз; річка: опеньки на вербах; біля рукавички — на корінні верби; путівники листяного лісу й біля річки, "Чим поживитись поруч із рукавичкою Під вербою" |
| Коли утеплювати рукавичку на узліссі? | окремої поради для узлісся немає, тож діє загальна порада для всього лісу: у листопаді, "Календар сезонів" |
| Коли утеплювати рукавичку у соснах? | у жовтні, за порадою хвойного лісу; листопад із "Календаря сезонів" окремо, як загальніша порада |
| Чим утеплити рукавичку під вербою? | поради листяного лісу й річки, і чия яка |
| Коли Ведмідь лягає спати? | за правилами "У ліщині", де живе Ведмідь |
| Що їсти в хвойному лісі? | порада хвойного лісу, без порад окремих рукавичок |
| Скільки внесок? | бот перепитує рукавичку кнопками |
| Чим лікувати застуду в зайченяти? | такої поради немає, бот нічого не вигадує |

3. Надішліть [docs/samples/Пожежа Під дубом.txt](docs/samples/Пожежа%20Під%20дубом.txt): бот попросить назватися, сам визначить місце (рукавичка "Під дубом") і збереже документ. Тепер "Що робити при пожежі під дубом?" отримує спершу пораду звіра з іменем і датою, а пам'ятку "Що робити при пожежі" окремо.
4. [Гриби зранку.txt](docs/samples/Гриби%20зранку.txt) місця не має, тож бот питає його кнопками. [Внески двох рукавичок.txt](docs/samples/Внески%20двох%20рукавичок.txt) бот не зберігає одразу, а просить розділити або обрати одне місце для всього документа.

Без Telegram, коли архів уже завантажено:

```bash
docker compose run --rm bot python -m bot.ask "скільки внесок під дубом?"
docker compose run --rm bot python -m bot.check   # 16 еталонних питань на живій моделі
```

## Як користуватися

- **Питання** — текстом, із місцем: "скільки внесок під дубом?". Якщо відповідь залежить від рукавички, а її не названо, бот перепитує кнопками. Після відповіді можна коротко: "а у соснах?".
- **Коли всі моделі Groq зайняті**, бот обіцяє відповідь і надсилає її протягом приблизно 10 хвилин, починаючи з самого питання (`На Ваше питання "…":`), а якщо модель так і не звільнилася, перепрошує. `/cancel` зупиняє це очікування.
- **Документи** — файлом PDF, Word (.docx, .doc) чи TXT до 20 МБ. На першому бот просить назватися. Місце можна вказати в підписі ("для Під вербою"), інакше бот визначає його з тексту або питає. Один документ — одне місце. Файл із тією самою назвою для того самого місця замінює Ваш попередній.
- **Команди**: `/my` — Ваші документи й видалення, `/name` — ім'я для підпису, `/invite` — запрошення для сусіда, `/invited` — запрошені й закриття доступу чужому, `/help`, `/cancel`.
- **Доступ.** Адмінів немає, запрошує будь-який звір у боті. Закрити доступ чужому може той, хто його запросив, або будь-хто вище в ланцюжку; разом із ним доступ утрачають ті, кого запросив він, а їхні документи перестають діяти.

## Як це працює

```
Telegram ──> handlers ──> файл:  extract (PDF/DOCX/TXT, OCR) ──> classify (місце) ──> storage
                     └──> текст: answering ──> places (місце з питання)
                                          ──> search (BM25 на кожному рівні) + легка модель за назвами
                                          ──> Groq (лише з наданих документів) ──> джерела з бази
                                 усі моделі зайняті ──> handlers: ще раз у фоні, до ~10 хв
Google Диск ──> archive (кожні 10 хв) ──> storage (версії, чинна одна)
```

- Модель бачить лише поради для місця з питання, від конкретніших до загальніших: рукавичка, її частина лісу ("Карта лісу"), увесь ліс. Якщо в різних місцях поради на тему різні (утеплення, гриби), відповідь про рукавичку чи частину лісу каже, чия яка порада, а загальнішу позначає: "Загальна порада для всього лісу — …"; спільну для всіх пораду (мисливці, пожежа) дає одразу.
- Джерела, автора й час бот бере з бази, тож вони не вигадані; відповідь без джерела не показується. Календар у запиті лише такий, якого потребує питання.
- Якщо відповідь порушує правила (рівні, архів, обидві частини лісу "Під вербою", пропущені пункти), бот один раз перепитує модель і бере кращу відповідь.

## Обмеження

- Безкоштовний рівень Groq дає кожній моделі 8000 токенів на хвилину, 200 тис. токенів і 1000 запитів на день; до хвилинного ліміту йде і промпт, і максимальна довжина відповіді.
- Питання — зазвичай два запити: вибір документів за назвами на найменшій моделі (до 400 токенів відповіді) і відповідь на `gpt-oss-120b` (до 12 тис. символів документів, 1500 токенів відповіді; 2000 і довше міркування лише питанням про конкретні дні: від сьогодні чи за днем тижня). Виправлення відповіді — ще один запит.
- 30 жовтня, до скорочення календаря й вибору, добового ліміту `gpt-oss-120b` вистачало на 30-45 відповідей; далі відповідають слабші `gpt-oss-20b` і `qwen3.8-27b`. Ключ Groq спільний для бота й `bot.check`, тож прогони еталонних питань теж витрачають ліміт. Для більшого лісу потрібен платний рівень Groq.
- Відкладені відповіді живуть лише в пам'яті: перезапуск їх губить. Чекати можуть до трьох питань одного звіра.
- Без `GOOGLE_API_KEY` сторінка теки дає дату без часу (дві версії одного дня точно впорядкує лише ключ), а якщо Google змінить її розмітку, новий екземпляр бота без ключа архіву не отримає.

## Тести

```bash
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest
.venv/bin/ruff check .
```

Тести покривають місця, версії документів, архів, вибір документів, календар і повні діалоги через підставні Telegram і модель. Тест старого .doc потребує antiword і без нього пропускається. GitHub Actions на кожен push запускає тести (з antiword) і ruff, а також збирає образ Docker ([.github/workflows/ci.yml](.github/workflows/ci.yml)).

## Структура

```
bot/  __main__ (запуск), handlers (діалоги, відповіді пізніше), answering (відповідь, календар),
      places (місця), search (BM25), classify (місце документа), archive (Google Диск),
      extract (PDF/DOCX/TXT, OCR), storage (SQLite), fsm (стан діалогів), llm (Groq),
      ask, check, invite (команди з термінала), texts, assets (аватарка)
tests/
docs/ розмова, як це працює, приклади документів
```
